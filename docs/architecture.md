# 项目架构与维护边界

## 权威来源

- `config/baseline_1.json`、`config/baseline_2.json`：两套冻结策略的权威配置。
- `scripts/core/`：正式规则实现；禁止放入参数网格、候选生成或研究分支。
- `scripts/daily/`：日常更新入口，只读取冻结配置，不修改参数。
- `research/`：研究过程、证据和带日期快照；保留现有路径以维持引用。
- `reports/`：面向阅读的当前汇总报告；不作为模型输入。
- `基准1/`、`基准2/`：互相独立的本地运行包、过程记录和正式结果。

## 内容流向

```text
公共/本地行情 → scripts/data → scripts/core → scripts/daily
                                      ↓
                            research/baseline-1
                                      ↓
                                  reports
```

研究结论不会自动进入正式策略。若未来恢复策略研发，应先在独立研究分支记录协议、样本边界和失败结果；只有明确批准后，才能更新配置和核心实现。

## 文件规则

1. 搜索、调参、重训练、临时候选和一次性比较脚本不得放回活动 `scripts/`。
2. 每个当前主题只维护一个权威报告；阶段材料可以归档，但不能与主报告并列更新。
3. 个人本金、成本、持仓、订单和操作计划只放 `private/`。
4. `tmp/`、Python运行环境、缓存和生成输出不进入Git。
5. 根目录不生成 `基准1.zip` 或 `基准2.zip`；两套基准继续以独立文件夹维护。
